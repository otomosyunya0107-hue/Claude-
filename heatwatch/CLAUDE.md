# CLAUDE.md — HeatWatch

本ファイルは `docs/requirements.md` §17.1 に基づく必須指示である。要件全体は
`docs/requirements.md`（本プロジェクトの唯一の仕様書、"本書"）を参照すること。

> **最重要**：HeatWatch は関係の判定装置ではなく、自分自身への早期警告装置である。
> 出力先は常に自分ひとり。相手を評価・採点・診断せず、相手向けの出力を一切生成しない。

## Privacy（P0-ETH-06 / DAT-104 / NFR-106）

- 会話本文・実名を、ログ・SQLite・例外メッセージ・レポート・テスト fixture・
  コミットへ出力しない。
- デバッグ・テストは合成データ（`tests/fixtures/`）のみで行う。実データは
  リポジトリ配下に置かない（`~/heatwatch-data/` 等）。
- 本文はプロセスメモリ上でのみ扱う。永続層（`storage`）は本文を受け取る
  インターフェースを持たない。
- センチネル試験（§15.2）を壊さないこと。`HEATWATCH_SENTINEL_*` はメモリ以外の
  どの永続層にも出現してはならない。

## Ethics（P0-ETH-02 / 03 / 04）

- 相手向け出力・相手個人スコア・関係性スコアを生成するコードを追加しない。
- 通知テンプレートは静的定数のみ（`notify/templates`）。動的な文字列連結で
  本文・引用・相手の発言要約を通知に含めない。
- 禁止語（悪い・落ち着い・感情的・責め・我慢・謝）を通知文へ入れない
  （NOT-102）。
- Safety 語彙検知時は通常のヒート通知を抑止し、静的な安全案内のみ表示する
  （P0-ETH-05 / DET-104、Fail Closed）。

## Architecture（§15.1）

- 層間依存は一方向のみ：
  `cli → evaluation/detector → features → ingest`、`notify → detector`。
- `storage` は全層から利用可だが、本文を受け取らない。
- `features` 層以下にネットワーク依存パッケージを追加しない
  （P0-ETH-06 をアーキテクチャで担保）。

## Evaluation（§12 / EVA-106）

- ホールドアウト（直近30%）を用いた評価を無断で繰り返さない。校正は校正セット
  （古い側70%）のみで行う。ホールドアウト評価は3回を超えたら警告する。
- ベースラインは `normal` 区間のみから一度だけ算出する固定定数（DEC-106）。
  オンライン学習を行わない。

## Workflow

- 実装前に対象要件 ID を列挙する。テストを先に書く。
- コミット完了前に次を通す：
  `uv run ruff check && uv run mypy && uv run pytest`
- DoD：要件 ID・テスト・センチネル試験・rollback 手順をコミット/PR に記載する。

## Go/No-Go

Phase 1（M1〜M5）の遡及評価で Lead Time 中央値が 0 以下なら、本システムに価値は
ない。Phase 2 へ進まず終了する（§4.1 G-C）。M5 で終了する可能性を前提に設計する。
