# ADR-0001: P0 不変条件の確定

- 状態: Accepted
- 日付: 2026-07-25
- 関連: requirements.md §6（倫理・同意・安全の不変条件）、文書管理（変更管理）

## 背景

HeatWatch は自己監視型ツールであり、利用者自身が非対称な関係の被害側である
可能性がある。この前提を無視した設計は、自己抑制の強化や本文流出という形で
利用者を害しうる。requirements.md は P0 群を「機能要件より上位の不変条件」と
位置づけ、その変更に ADR 記録を必須とした（変更管理）。本 ADR は初期時点の
P0 不変条件を確定する。

## 決定

以下を P0 不変条件として確定し、実装・依存関係・CI・テストで担保する。

- P0-ETH-01 パートナーへの開示（Phase 2 の前提条件）
- P0-ETH-02 相手向け出力の不在（送信系クライアントを依存に含めない）
- P0-ETH-03 相手プロファイルの非永続化（禁止列をスキーマに持たない）
- P0-ETH-04 非難構文の禁止（通知テンプレートは静的定義のみ）
- P0-ETH-05 安全分岐（Safety 検知時は通常通知を抑止、Fail Closed）
- P0-ETH-06 ローカル完結（features 層以下にネットワーク依存を持ち込まない）
- P0-ETH-07 反芻の抑制（常設ダッシュボードを実装しない）

これらは §17.2 の hook、§15.2 センチネル試験、§15.1 アーキテクチャ制約
（依存関係を持たせない）の三重で担保する。

## 帰結

- 変更するには、変更前にパートナーへ再説明し（承認手続き）、本 ADR を更新または
  後続 ADR を追加する。
- クラウド LLM 利用（OPT-201）や送出を伴う機能は、本 ADR とは別の ADR で
  明示的に記録しない限り導入しない（DEC-104）。
